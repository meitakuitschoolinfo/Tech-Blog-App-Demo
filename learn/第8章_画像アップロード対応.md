# 📘 第8章

## 画像アップロード対応
― **URL入力 → ファイルアップロード** に切り替え、即時プレビューもできるようにする ―

> 📌 第5章では「画像はURL入力」で実装していました。
>    この章ではそれを **ローカルファイルアップロード方式** に置き換え、
>    あわせて発生していた **ブログ登録時のテンプレートエラー** も修正します。

## 🎯 8-1. この章のゴール（重要）

この章を終えたら、次のことが **説明できる状態** を目指します。

✔ **`MultipartFile`** で画面からアップロードされたファイルを受け取れる
✔ アップロードファイルを **ローカルディスクに保存** して、**`/uploads/**`** で配信できる
✔ ファイル選択直後に **JavaScript（FileReader）で即時プレビュー** ができる
✔ `enctype="multipart/form-data"` がなぜ必要か説明できる
✔ **`@ModelAttribute("blogForm")`** を付けなければならない理由を説明できる
✔ アップロード方式に切り替えるための **層をまたいだ変更の流れ** が書ける

## 🐛 8-2. まず発生した不具合：テンプレートエラー

ブログ登録 (POST `/admin/blogs`) を叩くと以下のエラーが出ていました：

```
Exception processing template "admin/blog/form":
Error during execution of processor
'org.thymeleaf.spring6.processor.SpringInputGeneralFieldTagProcessor'
(template: "admin/blog/form" - line 53, col 48)
```

### 原因

Controller の POST メソッドはこう書かれていました：

```java
@PostMapping("/admin/blogs")
public String register(
        @Valid BlogRegisterForm blogForm,       // ← パラメータ名は blogForm
        BindingResult bindingResult,
        ...
```

しかし、**Spring が Model に入れる名前は「クラス名の先頭小文字」** がデフォルトです：

```text
BlogRegisterForm → blogRegisterForm   ← Spring が勝手にこの名前で入れる
```

→ テンプレートは `th:object="${blogForm}"` を参照
→ **モデルには blogForm は存在しない（あるのは blogRegisterForm）**
→ `th:field="*{title}"` 等が「null をバインドできない」エラー

### 修正

`@ModelAttribute("blogForm")` を付けて **明示的に名前を揃える**：

```java
@Valid @ModelAttribute("blogForm") BlogRegisterForm blogForm,
```

これで `model.addAttribute("blogForm", blogForm)` と等価になる。

> ⚠️ **教訓**：`@Valid Form form` だけ書くと **Springが命名規則で勝手にキー名を決める**。
>    テンプレートと **キー名が違うとエラーになる** ので、`@ModelAttribute(...)` で揃えるのが安全。

### 同じ修正を Edit にも

`BlogEditController` も同じ問題があるので同様に修正：

```java
@Valid @ModelAttribute("blogForm") BlogEditForm blogForm,
```

> ✅ 他の Controller（`UserRegisterController` / `MyPageController` / `AdminCategoryController`）は
>    パラメータ名が `userRegisterForm` / `categoryForm` で **クラス名と一致** していたので問題なし。

| 方式                       | メリット                              | デメリット                                |

## 🧱 8-5. ★中心ファイル★ FileStorageService

完成ファイル：[FileStorageService.java](../src/main/java/com/meitaku/blog/service/FileStorageService.java)

### 役割

> アップロードされた `MultipartFile` を **ローカルディスクに保存** して、
> ブラウザがアクセスできる **公開URL（`/uploads/xxx.jpg`）** を返す。

### コードの要点

```java
@Service
public class FileStorageService {

    private final Path uploadDir = Paths.get("uploads");

    @PostConstruct
    public void init() {
        Files.createDirectories(uploadDir);  // ディレクトリが無ければ作る
    }

    public String store(MultipartFile file) {
        if (file == null || file.isEmpty()) return null;   // 任意項目への対応

        String ext = ...;                              // 拡張子を抽出
        String filename = UUID.randomUUID() + ext;     // 衝突しないファイル名
        Path target = uploadDir.resolve(filename);
        file.transferTo(target.toAbsolutePath());      // ★保存
        return "/uploads/" + filename;                 // ★公開URLを返す
    }
}
```

### ポイント

| ポイント                   | なぜ？                                                    |
| -------------------------- | --------------------------------------------------------- |
| `@PostConstruct` で初期化   | Bean生成直後に**必ず1回**保存ディレクトリを用意する        |
| `UUID` でファイル名生成     | 「同名ファイルが連続でアップロードされた時の衝突」を防ぐ   |
| 拡張子を残す                | `.jpg` `.png` を保ってブラウザが正しく Content-Type を判定 |
| `file.isEmpty()` で早期 return | 任意項目で「ファイル未選択」時に null を返す簡潔さ      |
| `IOException` を非チェックに包む | 呼び出し側（Service）が `throws` だらけにならない        |

### 保存場所

- プロジェクト直下 `uploads/` フォルダ
- Spring Boot を `mvnw spring-boot:run` で起動した時の **カレントディレクトリ** がプロジェクトルート
- 本番ではこのパスを **環境変数化** ＋ **`/var/lib/techblog/uploads`** などに変える

## 🧱 8-6. WebMvcConfig：`/uploads/**` で配信

完成ファイル：[WebMvcConfig.java](../src/main/java/com/meitaku/blog/config/WebMvcConfig.java)

```java
@Configuration
public class WebMvcConfig implements WebMvcConfigurer {
    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        registry.addResourceHandler("/uploads/**")
                .addResourceLocations("file:./uploads/");
    }
}
```

### なぜ必要？

- `FileStorageService` がファイルを `uploads/` に保存する
- でも **ブラウザは「物理パス」じゃなく「URL」でリクエストする**
- → `/uploads/abc.jpg` のリクエストを `./uploads/abc.jpg` に解決するマッピングが必要

### `file:` 接頭辞の意味

- デフォルトの `classpath:` は **JAR内リソース** を指す
- アップロード画像は **ファイルシステム** にある
- → **`file:`** を付けてファイルシステムのパスを指定

### 末尾の `/` を忘れない

```java
.addResourceLocations("file:./uploads/")   // ⭕
.addResourceLocations("file:./uploads")    // ❌ 動かない
```

末尾スラッシュが無いと Spring がフォルダと認識しない。

## 🧱 8-7. Form の変更：MultipartFile 追加

完成ファイル：[BlogRegisterForm.java](../src/main/java/com/meitaku/blog/form/blog/BlogRegisterForm.java)
            ／ [BlogEditForm.java](../src/main/java/com/meitaku/blog/form/blog/BlogEditForm.java)

### 旧（URL入力方式）

```java
@Size(max = 500)
private String imageUrl;
```

### 新（アップロード方式）

```java
private MultipartFile imageFile;   // ★ 新規アップロード
private String imageUrl;           // ★ 既存URLを編集時に round-trip
```

### なぜ **両方** 持つの？

| フィールド    | 用途                                                              |
| ------------- | ----------------------------------------------------------------- |
| `imageFile`   | ユーザーが **新たに選んだ** ファイル                              |
| `imageUrl`    | **既に保存済み** の画像URL（編集画面初期表示／hidden で往復）     |

→ 編集画面では：

- 既存画像が **`imageUrl`** からプレビュー表示される
- ユーザーが **何も選ばなければ** `imageFile` は空 → 既存URLが維持される
- ユーザーが **新ファイルを選べば** `imageFile` から新URL生成 → 上書き

新規登録時は `imageUrl` は **null** のまま使われない（テンプレート側で空判定）。

### バリデーション

- `MultipartFile` 自体に `@Size` 等は不要（multipart 上限は `application.properties` で）
- 任意項目なので `@NotNull` も付けない
- 高度には `@ValidImageFile` のようなカスタムバリデータを作る場合もあるが、本研修では省略

## 🧱 8-8. Service の変更：FileStorageService を注入して呼ぶ

完成ファイル：[BlogService.java](../src/main/java/com/meitaku/blog/service/BlogService.java)

### register（新規登録）

```java
@Transactional
public Blog register(BlogRegisterForm form) {
    ...
    blog.setImageUrl(fileStorageService.store(form.getImageFile()));
    //                                        ↑
    //                          ファイル未選択なら null が入る
    ...
}
```

### update（更新）

```java
@Transactional
public Blog update(BlogEditForm form) {
    ...
    String newUploadedUrl = fileStorageService.store(form.getImageFile());
    if (newUploadedUrl != null) {
        blog.setImageUrl(newUploadedUrl);        // 新ファイルがあれば上書き
    } else {
        blog.setImageUrl(form.getImageUrl());    // なければ hidden で来た既存URLを維持
    }
    ...
}
```

### ポイント

| ポイント                              | 理由                                              |
| ------------------------------------- | ------------------------------------------------- |
| **`MultipartFile` を Service が受ける** | 「ファイルの保存」は業務ロジックの一部             |
| **保存→URL生成は FileStorageService** | Single Responsibility（責務の分割）                 |
| **update の既存URL維持ロジック**       | 「無編集なら現状維持」が一番自然な挙動             |
| ハッシュ化ロジックと似た構図           | 「外部リソースに副作用を起こす処理」は Service の仕事 |

## 🧱 8-10. テンプレートの変更：file input ＋ 即時プレビュー

完成ファイル：[admin/blog/form.html](../src/main/resources/templates/admin/blog/form.html)

### 変更①：`<form>` に `enctype` 追加

```html
<form ... enctype="multipart/form-data">
```

**これが無いと MultipartFile は空のまま届く** という典型バグ。

### 変更②：URL input → file input

```html
<!-- 既存URLを hidden で round-trip（編集時の継続用） -->
<input type="hidden" th:field="*{imageUrl}">

<!-- ファイル選択 -->
<input type="file" th:field="*{imageFile}" accept="image/*"
       onchange="previewImage(event)">
```

| 属性                | 意味                                              |
| ------------------- | ------------------------------------------------- |
| `type="file"`       | ファイル選択ダイアログを開く                      |
| `accept="image/*"`  | ダイアログを画像ファイルのみに絞る（UXの改善）    |
| `onchange="..."`    | 選択直後に JS を呼んでプレビューを差し替える      |

### 変更③：プレビュー領域

```html
<img id="imagePreview"
     th:src="${!#strings.isEmpty(blogForm.imageUrl)} ? ${blogForm.imageUrl} : ''"
     th:style="${!#strings.isEmpty(blogForm.imageUrl)} ? 'display:block' : 'display:none'"
     alt="プレビュー">
```

- 初期：**既存URLがあれば既存画像を表示**、なければ非表示
- ファイル選択後：JS が `src` を **Base64 (data URL)** に差し替えて表示

### 変更④：プレビュー用 JavaScript

```javascript
function previewImage(event) {
    const file = event.target.files && event.target.files[0];
    if (!file) return;
    const reader = new FileReader();
    reader.onload = function (e) {
        const img = document.getElementById('imagePreview');
        img.src = e.target.result;       // ★ data URL を img に注入
        img.style.display = 'block';
    };
    reader.readAsDataURL(file);          // ★ ファイルを data URL として読む
}
```

### `FileReader` とは？

- ブラウザ標準API
- 選択ファイルを **サーバーに送らずに** Base64 文字列として読める
- → **ネットワーク経由ではなく** クライアントだけで即プレビューが可能

## 🧱 8-11. SecurityConfig の変更：`/uploads/**` を公開

完成ファイル：[SecurityConfig.java](../src/main/java/com/meitaku/blog/config/SecurityConfig.java)

```java
.requestMatchers(
    "/", "/blogs", "/blogs/**", "/login", "/admin/register",
    "/css/**", "/js/**", "/images/**",
    "/uploads/**"   // ★ 追加：公開ブログ画面でも画像が表示できるように
).permitAll()
```

### なぜ必要？

- 公開ブログ一覧／詳細画面で **未ログインユーザーが画像を見る**
- もし permitAll に入っていないと、**画像取得が認証要求 → ログイン画面へリダイレクト** → 画像が表示されない

## 🧱 8-12. application.properties の変更：multipart 上限

完成ファイル：[application.properties](../src/main/resources/application.properties)

```properties
spring.servlet.multipart.max-file-size=10MB
spring.servlet.multipart.max-request-size=10MB
```

| プロパティ                                    | 意味                                            |
| --------------------------------------------- | ----------------------------------------------- |
| `spring.servlet.multipart.max-file-size`      | **1ファイル** あたりの最大サイズ                |
| `spring.servlet.multipart.max-request-size`   | リクエスト全体（複数ファイル＋テキスト）の最大  |

### 既定値の罠

Spring Boot の既定は **1MB**。スマホで撮った写真は普通に超えるため、**画像アップロードを使うなら必ず明示**する。

超えた場合は `MaxUploadSizeExceededException` が飛ぶ。

## 📁 8-13. データの流れ（最終形）

```text
[ブラウザ]
   │ ① <input type="file"> で画像選択
   │   → FileReader でローカル即プレビュー（サーバー往復なし）
   │
   │ ② フォーム送信（enctype="multipart/form-data"）
   ▼
[Controller: @Valid @ModelAttribute("blogForm") BlogRegisterForm]
   │   ↓ blog登録の Form 検証
   ▼
[Service: BlogService.register]
   │   ├─ Category 解決
   │   └─ FileStorageService.store(file)
   │           │
   │           └─ uploads/{UUID}.jpg として保存
   │           └─ "/uploads/{UUID}.jpg" を返す
   ▼
[Entity: blog.setImageUrl("/uploads/{UUID}.jpg")]
   │
   ▼
[DB]
   blogs テーブル.image_url に "/uploads/xxx.jpg" として保存

────────────────────────────────────────────

[ブラウザが /uploads/xxx.jpg をリクエスト]
   │
   ▼
[WebMvcConfig: /uploads/** → file:./uploads/]
   │
   ▼
[SecurityConfig: /uploads/** は permitAll]
   │
   ▼
[ローカルファイル ./uploads/xxx.jpg を返す]
```

## ❌ 8-14. つまづきやすいポイント

| 症状                                              | 原因                                                          |
| ------------------------------------------------- | ------------------------------------------------------------- |
| `MultipartFile imageFile` が常に **null/empty**    | フォームに `enctype="multipart/form-data"` が無い              |
| アップロード後、画像が表示されない（404）         | `WebMvcConfig` の resource handler 未登録／`file:` パス末尾 `/` 漏れ |
| アップロードが **MaxUploadSizeExceededException** | `application.properties` のサイズ上限を変えていない           |
| 画像表示時に **ログイン画面に飛ぶ**               | `SecurityConfig` で `/uploads/**` を permitAll していない     |
| バリデーション失敗の再描画で **テンプレートエラー** | `@ModelAttribute("blogForm")` を付け忘れている                |
| 「同名ファイルが上書きされる」                    | `UUID` 等で衝突回避していない                                 |
| プレビューが更新されない                           | JavaScript の `onchange` が動いていない／`#imagePreview` セレクタの誤り |
| アップロード後ファイルが見つからない              | 起動時のカレントディレクトリが想定と違う（IDEから実行時など） |

## ✨ 8-15. ポイント（必読）

### ポイント①：**`enctype="multipart/form-data"` は MultipartFile の前提条件**

これが無いと永遠に空で届く。**最初に確認するチェックリスト**。

### ポイント②：**ファイル保存はサービス層**

`FileStorageService` のような専用クラスに切り出す。
パスワードハッシュ化と同じく **「副作用のある処理」は Service**。

### ポイント③：**新ファイル無しで「既存画像を維持」**

hidden で `imageUrl` を round-trip させる。
Service 側は **「新ファイル有り → 上書き／無し → そのまま」** で分岐。

### ポイント④：**`@ModelAttribute("blogForm")` でキー名を揃える**

Springのデフォルト命名規則とテンプレートの参照名を **明示的に一致** させる。
今回のエラーの直接原因。

### ポイント⑤：**JS の即時プレビューは FileReader**

サーバーアップロード前に **クライアント側だけで** 表示可能。UXが大きく改善する。

### ポイント⑥：**配信URLは `WebMvcConfig` ＋ `SecurityConfig` の二段階**

- WebMvcConfig：物理パスをURLに紐づける
- SecurityConfig：そのURLを認証不要にする

両方やらないと画像が出ない。

### ポイント⑦：**multipart 上限は明示する**

Spring Boot のデフォルト 1MB は画像アップロードには **小さすぎる**。
忘れがちなので **必ずチェック**。

### ポイント⑧：**保存先パスは将来 環境変数化**

研修中は `./uploads/` でOK。本番では `@ConfigurationProperties` でパス・サイズを設定化する。

## ✅ 8-16. 第8章まとめ

✔ `MultipartFile` を Form に持たせて画像アップロードを受け取る
